## Часть 1. Дизайн теста

### Размер выборки

Сравнение двух долей, двусторонний тест:

```
n = (z(1-α/2) + z(1-β))² · [p1(1-p1) + p2(1-p2)] / Δ²
```

Значения: z(1-α/2) = 1,96; z(1-β) = 0,84; p1 = 0,030; p2 = 0,033; Δ = 0,003.

```
n = 2,8² · (0,0291 + 0,0319) / 0,003² ≈ 53 200 поисков на группу
```

### Допущения

1. **Доля подходящих запросов s = 30 %.** Анализ ведём только по ним: на остальных тест ничего не меняет, и эффект +10 % разбавился бы. Базовый CTR на этом подмножестве 3 %.
2. **Рандомизация по пользователю, анализ по поискам.** Поиски одного человека коррелируют, поэтому вводим design effect: `DEFF = 1 + (m − 1) · ρ`, где m число подходящих поисков на пользователя за тест, ρ = 0,05. CTR считаем как отношение сумм, дисперсию оцениваем дельта-методом или бутстрэпом по пользователям.
3. **Длительность 14 дней.** Максимум по условию, два полных недельных цикла и сглаживание эффекта новизны.

### Расчёт

```
Подходящих поисков на пользователя в день: 4 · 0,6 · 0,3 = 0,72
За 14 дней: m ≈ 10
DEFF = 1 + 9 · 0,05 = 1,45
Пользователей на группу: 53 200 · 1,45 / 10 ≈ 7 700
```

| Сценарий | Пользователей на группу |
|---|---|
| Базовый (s = 30 %, ρ = 0,05) | ~7 700 |
| ρ = 0,02 / ρ = 0,10 | ~6 200 / ~10 100 |
| s = 20 % / s = 50 % | ~10 200 / ~5 700 |

С запасом на неточность ρ и s берём **10 000 пользователей на группу**.

### Контроль теста

- A/A-тест перед запуском
- Проверка SRM (баланс групп)
- Фиксированный горизонт, без подглядывания
- Guardrail-метрики: конверсия поиска в заказ, доля поисков без клика, доля пустых выдач, латентность

## Часть 2. Правила отбора запросов

Запрос подходит, если он **широкий** (фильтры по типу товара не помогают) и **модель умеет по нему предлагать теги**. Метрики считаем по логам за 30 дней.

| № | Метрика | Порог (стартовый) |
|---|---|---|
| 1 | Доля топ-1 типа товара среди топ-50 выдачи | < 50 %, и ≥ 3 типов с долей ≥ 10 % |
| 2 | Доля сессий с переформулировкой запроса | ≥ 25 % |
| 3 | CTR текущих тегов-фильтров на запросе | ниже медианы по всем запросам |
| 4 | Число поисков запроса за 30 дней | ≥ 100 |
| 5 | Суммарная вероятность топ-3 тегов модели | ≥ 0,3 |

**Исключения:** брендовые, навигационные и модельные запросы («iphone 15», артикулы), где фильтры по атрибутам работают хорошо.

Правило 1 основное, остальные его уточняют. Пороги подбираем по процентилям так, чтобы охват составил 20–40 % поисков с тегами.

### Проверка до запуска

1. **Разметка.** 300 случайных запросов, два асессора размечают «широкий / узкий», κ ≥ 0,6. Правила должны давать precision ≥ 0,8 и recall ≥ 0,6.
2. **Качество модели.** hit-rate@3 на отобранных запросах заметно выше, чем на отброшенных.
3. **Охват.** Доля отобранных запросов в трафике и есть s для Части 1. Если она сильно отличается от 30 %, пересчитываем выборку.
4. **Стабильность.** Пересечение набора запросов между соседними месяцами ≥ 80 %.
5. **Фиксация.** Пороги и правила фиксируем до старта и во время теста не меняем.
